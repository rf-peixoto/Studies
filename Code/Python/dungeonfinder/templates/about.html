What is a code cave?

A code cave is a contiguous run of padding bytes (commonly 0x00, 0xCC, or 0x90) left inside a compiled binary — the slack between sections, alignment gaps, or zeroed data regions. Reverse engineers and malware analysts study them to understand a file's layout and to spot where foreign code could be hidden.

DungeonFinder locates and characterizes those caves. It is strictly a detection and identification tool.

What DungeonFinder does

  • Parses PE, ELF and Mach-O headers (via LIEF): format, architecture, entry point, section table.
  • Computes per-section Shannon entropy to flag packed/encrypted regions.
  • Fingerprints the file with MD5 / SHA-1 / SHA-256.
  • Scans for padding runs on one or more byte patterns, with section, offset and alignment filters.
  • Optionally runs a Capstone disassembly pass to tell padding apart from stray code.
  • Reports statistics, a size distribution, an offset-accurate cave map, and JSON/CSV export.

What it does not do

DungeonFinder never modifies a binary. There is no shellcode injection, no new-section creation, no entry-point redirection, no certificate stripping and no checksum patching. Every upload is opened read-only, analyzed, and deleted after the retention window.

Use it on files you are authorized to analyze.
